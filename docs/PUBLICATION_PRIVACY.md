# 公開時のプライバシー確認

## 公開前

- `npm ci`、`npm test`、`npm run build`を実行し、`dist/`監査を通す。
- `dist/`だけを新しい空の公開リポジトリへ置く。親フォルダの `.git`、元履歴、remote、作者設定をコピーしない。
- 公開主体のユーザー名、メール、Organization、プロジェクト名、ドメイン、プロフィール、Actionsログが本人と結び付かないか確認する。
- `dist/`にバックアップ、画像原本、テスト成果物、ソースマップ、環境ファイルがないことを確認する。
- `noindex` は検索エンジンへの依頼にすぎず、アクセス制御ではない。URLを知る人、ホスティング事業者、アクセスログからは閲覧・追跡され得る。

## GitHub Pages

- 本人と結び付かない新しいアカウントまたはOrganizationと、履歴のない独立リポジトリを使う。
- `*.github.io` は同一ホスト内のサブパスが同一オリジンになる。別アプリとのデータ境界が必要なら、専用ホストまたは専用カスタムドメインを使う。
- Actionsは標準のbuild成果物だけを公開し、ログにローカルパスや秘密情報を出さない。
- リポジトリのcommit author名・メール、プロフィール、公開活動から関連が推測されないか確認する。

## Cloudflare Pages

- 新規プロジェクト名と専用ドメインを使い、元リポジトリを連携しない。手動アップロードなら監査済み `dist/` だけを使う。
- Cloudflareアカウント、チーム名、既存ドメイン、DNS、Analytics、Web Analytics beaconが本人や元サイトと結び付かないか確認する。
- 自動挿入される解析・外部スクリプトを無効にし、CSPと通信監査を再確認する。

## iPhone実機

1. Safariで公開URLを開き、表示名、アイコン、URLに旧識別情報がないことを確認する。
2. 初回に架空人物5人だけが表示されることを確認する。
3. ホーム画面へ追加し、名称、アイコン、standalone表示、セーフエリアを確認する。
4. 月切替、詳細、登録、編集、削除、長押し日付変更、スクロール、キーボード表示を確認する。
5. 日英、ライト／ダーク、画像追加、回転、390px前後の幅で崩れがないことを確認する。
6. 暗号化バックアップをFilesへ保存し、正しいパスワード、誤パスワード、旧ZIP、過去の暗号化ファイルを確認する。
7. 機内モードで再起動し、PWAがオフライン表示できることを確認する。
8. リセット後に5人へ戻り、別サイトや他アプリのデータが変化しないことを確認する。
9. SafariのWeb Inspectorまたは別端末の開発者ツールでconsoleエラーと外部通信を確認する。

このローカル監査だけではiOS Safari、Files、ホーム画面PWA、パスワードマネージャーの実機挙動を保証できません。
